# AIの「静かな失敗」を検知するログ監視スクリプトを作った話

AIエージェントに作業を任せていると、ときどき怖くなる瞬間があります。

「これ、ちゃんと動いてるんだよな？」

動いているように見えて、裏側で静かに壊れていることがあります。エラーが画面に出ない、誰も止めない、でも確実にお金や時間が溶けている。いわゆる **サイレント・フェイル（静かな失敗）** です。

わたしはこれで一度、2万2千円を吹き飛ばしました。

## 事の発端は22,000円の課金事故

Gemini の画像生成をエージェントに任せていたところ、ある日のクレジットカード請求が跳ね上がっていました。原因はシンプルで、画像生成のリトライが暴走していたのです。ログファイルには「cost」「billing」といったキーワードが流れていたのですが、わたしが気づいたのは請求が確定したあと。

このときの詳しい顛末は別の記事に書いたのでここでは繰り返しません。問題は、**同じことを二度と起こさない仕組み**を作ることでした。

AIに任せる範囲を広げるほど、ログを人間が毎分眺めることは不可能になります。だから、代わりに眺めてくれる子を作ることにしました。

## 作ったもの：silent_fail_watcher.sh

やっていることはとても単純です。

- 監視対象のディレクトリに並ぶログファイルを、inotifywait で「追記があったとき」だけ起こす
- 追記された行を正規表現で ERROR / WARN / FALLBACK / COST / BILLING に分類する
- ERROR 相当（COST と BILLING も含む）は **即通知**
- WARN と FALLBACK は 5 分間バッファに溜めて **まとめて通知**
- 通知は ntfy でスマホに押し込む

「即通知」と「集約通知」を分けたのは、WARN まで即送ると夜中にスマホが鳴りっぱなしになるからです。放置してはいけない危険（請求系）は即、見逃してもいい程度の警告は後回し。メリハリが現場運用には効きます。

![ログ追記→正規表現分類→即通知とバッファ集約の2チャンネル](images/silent_fail_watcher_flow.png)

## 設計で気をつけた3つのこと

### 1. ポーリングしない

最初は tail を回しっぱなしにする案も考えました。ですが、エージェントが10体以上動いている環境ではログファイルの数が数十に膨らみ、tail プロセスが増えるほど CPU と記述子を食います。inotifywait を使うと、ファイルに書き込みがあったときだけカーネルが起こしてくれるので、待機中のコストがほぼゼロになります。

### 2. 追記分だけ読む

ログファイルは今この瞬間も増え続けています。毎回頭から読み直すと重い上に、一度通知した行が再度ヒットして二重通知になります。そこで各ファイルのサイズをオフセットとして保存しておき、**前回読んだ位置から後ろだけ** を取り出す形にしました。ファイルがローテートで小さくなっていたら、オフセットを 0 に戻します。

### 3. 自分のログを監視しない

これを忘れると悲惨です。監視スクリプト自身の出力ログを監視してしまうと、通知を出した行を自分で検知して、また通知を出して……の無限ループに入ります。自身のログと通知送信ログ、それに日報ファイルはすべて除外対象にしました。

重複通知を抑えるため、同一行は60秒以内に再通知しない dedup も入れてあります。同じエラーが1秒間に100回出ても、スマホには1回しか飛びません。

## 使ってみたら、既知の地雷が出てきた

走らせた初日、さっそく通知が鳴りました。

こちらがお願いしたわけでもないのに、既存の cron が6件ほど連続で失敗しているのを拾ったのです。いずれも静かに失敗していて、ダッシュボード上では「動いている風」になっていたやつら。22,000円のときと同じ構造です。

これは「監視しないと気づけなかった故障」です。作ってよかった、と素直に思いました。

## 自分の運用に取り入れるなら

もし似たものを自前で組むなら、最低限この3つがあれば回ります。

- ログの置き場所を1箇所か数箇所に寄せる（散らばっていると監視漏れが出る）
- ERROR / FAIL / FATAL / COST / BILLING を拾う正規表現を持つ
- 通知は **即時** と **集約** の2チャンネルに分ける

監視対象のキーワードに COST と BILLING を必ず入れてください。これを入れていなかったから、わたしは22,000円を見逃したわけですから。

## まとめ

AIに任せる範囲が広がるほど、「動いているか」を人間が見続けることは不可能になります。成功も失敗も静かで、気づいたときにはお金か時間が溶けている。

対策は **気づける仕組みを先に作る** こと。監視スクリプトの出来栄えより、「通知が飛んでくる状態にしておく」ことそのものが効きます。

同じように複数のスクリプトや cron を回している人は、似たものを1本持っておくと精神衛生が一段階上がるはずです。わたしはあの22,000円を払った代わりに、この監視スクリプトと夜ぐっすり眠れる感覚を手に入れました。

費用対効果は、ぎりぎり黒字です。
