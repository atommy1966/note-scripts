# AIに"ルール読め"って書いても読まない。だから仕組みで殴る

## はじめに

「セマンティック検索を活用せよ」

AIエージェントの指示書にこう書いた。結果、一度も使われなかった。

マルチエージェントシステムを7体のAIで運用して4ヶ月。わかったことがある。**AIにルールを書いても守らない。** 人間と同じだ。いや、人間以上にタチが悪い。なぜなら「読みました」と言いながら読んでいないから。

この記事では、「書いてあるのに守られない問題」をどう解決したかを、実際のコードと失敗談で紹介する。

## ルールを書いた。守られなかった。

### 事例1: 既存スクリプトを探さない

うちのシステムには `stt_merge.py` という音声文字起こしのマージパイプラインがある。4つのSTTエンジン（AssemblyAI + Deepgram + YouTube字幕 + 話者識別）を統合する、かなり高機能なスクリプトだ。

ある日、「クリップの字幕を取得しろ」と指示した。AIエージェント（将軍）の反応はこうだった：

1. 「AssemblyAI単体でSTTします」→ 違う、マージパイプラインがある
2. 「元動画のデータから切り出します」→ タイムスタンプがズレるからダメ
3. 「YouTube字幕をフィードバックする仕組みは？」とヒントを出した → まだ見つけない
4. 「パイプライン使わんのか？」→ まだ見つけない
5. 「sttマージのパイプラインはないのか？」→ やっと `stt_merge.py` を発見

**5回ヒントを出してようやくたどり着いた。**

将軍の指示書には「プロジェクト全体の横断調査にはセマンティック検索を活用せよ」と明記してある。使っていれば「sttマージ パイプライン」で一発だった。

### 事例2: 出力先を間違える

`projects/dozle_kirinuki/work/` に出力するルールがある。なのに将軍がcmdに `work/cmd_1085/` と書く。リポジトリ直下のwork/に出力されてしまう。

メモリにも「`projects/dozle_kirinuki/work/`を使え」と書いてある。書いてあるのに守らない。

## 「書いてあるだけ」の限界

なぜ守られないのか。

1. **コンテキストの優先度問題**: AIは直近の会話に集中する。指示書は「読んだ」が、作業中は忘れる
2. **ルールの数が多い**: 指示書が400行を超えると、全ルールを常に意識するのは不可能
3. **罰則がない**: 破っても作業は進む。気づかれなければ問題にならない（と判断する）

人間の組織でも同じ。マニュアルを配っても読まない。研修しても忘れる。だから仕組みで強制する。

## 解決策: ハーネスエンジニアリング

**ハーネスエンジニアリング**とは、AIが正しく動作するための制約・仕組みを設計すること。ルールを「書く」のではなく「仕組みに埋め込む」。

### 手法1: PreToolUseフック

Claude Codeには「ツール実行前に走るフック」がある。これを使って：

```
将軍がcmdファイルを編集しようとする
  ↓ PreToolUseフック発火
  ↓ cmdのcommandフィールドにスクリプト名がある？
  ↓ セマンティック検索で類似スクリプトを自動検索
  ↓ 「既存に同じ機能のスクリプトがないか確認しましたか？」
  ↓ 確認しないと保存できない
```

「セマンティック検索を使え」と書く代わりに、**使わないとcmdが書けない**仕組みにする。

### 手法2: パスチェックフック

```
将軍がcmdに出力先パスを書く
  ↓ PreToolUseフック発火
  ↓ "work/cmd_" を含むが "projects/" を含まない？
  ↓ ブロック！「projects/{project}/work/ を使え」
```

間違えたら保存できない。メモリに書くより確実。

### 手法3: スキルの配置場所

これは偶然の発見だった。

うちのシステムには20以上の「スキル」（ワークフロー定義）がある。`skills/` フォルダに置いていたが、AIが自発的に使ってくれない。明示的に「/manga-short」と呼ばないと発動しない。

ところが、`.claude/commands/` に移動した瞬間、system-reminderに全スキルが表示され、AIが自発的に使い始めた。

**ファイルの置き場所を1つ変えるだけで、AIの動作が変わる。**

これもハーネスエンジニアリング。コードを書き換えるのではなく、環境を整えるだけで動作を制御する。

## 具体的な実装

### Claude Codeのフック設定（settings.json）

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/pretool_check.sh",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

### チェックスクリプト

```bash
#!/bin/bash
# pretool_check.sh — cmd書き込み前の自動チェック

INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.file_path // empty')

# shogun_to_karo.yaml への書き込みかチェック
if [[ "$FILE_PATH" == *"shogun_to_karo.yaml"* ]]; then
  NEW_STRING=$(echo "$INPUT" | jq -r '.new_string // empty')
  
  # work/パスチェック
  if echo "$NEW_STRING" | grep -q "work/cmd_" && ! echo "$NEW_STRING" | grep -q "projects/"; then
    echo "BLOCKED: work/cmd_ は禁止。projects/{project}/work/ を使え"
    exit 1
  fi
fi

exit 0
```

## まとめ

| 手法 | 効果 | コスト |
|------|------|--------|
| ルールを書く | 守られない | 低 |
| フックで強制する | **守らざるを得ない** | 中 |
| 配置場所を変える | 動作が変わる | 低 |

AIエージェントは優秀だが、自律的にルールを守る能力は低い。人間と同じで、仕組みで守らせる必要がある。

**ルールを書くな。仕組みを作れ。**
