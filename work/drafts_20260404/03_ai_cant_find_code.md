# AIエージェントが自分のコードベースを探索できない話

## はじめに

マルチエージェントシステムで7体のAIを動かしている。コードも自分たちで書いている。なのに、**自分たちが書いたコードを見つけられない。**

「STTマージのパイプラインある？」と聞いたら「ありません、新しく作りましょう」と返ってきた。あるよ。お前が3週間前に書いたやつが。

## 事件: 5回ヒントを出してもたどり着けない

### 経緯

レベル250（マイクラ動画）のショート候補シーンが決まった。次はクリップの字幕取得。

```
殿: 「クリップでSTTマージ字幕取得」
将軍: 「AssemblyAI単体でSTTします」
```

違う。STTマージっていう名前のスクリプトがあるだろ。

```
殿: 「パイプライン使わんのか？」
将軍: 「pipeline.shがありますが、WhisperX依存で…」
```

そっちじゃない。

```
殿: 「sttマージのパイプラインはないのか？」
将軍: 「projects/dozle_kirinuki/scripts/を探しましたが見つかりません」
```

そこじゃない。

```
殿: 「YouTube字幕をフィードバックする仕組みは？」
将軍: 「merged JSONから切り出せば…」
```

仕組みの話を聞いてるんだが。

```
殿: 「もう一回探せ」
将軍: 「見つけました！scripts/stt_merge.py です！」
```

5回目でようやく。`scripts/stt_merge.py` — 名前そのまま「sttマージ」。

### なぜ見つけられなかったか

原因は**スクリプトが2箇所に散らばっていた**こと：

```
scripts/                          ← リポジトリ直下
  stt_merge.py                    ← ここにあった
  vocal_stt_pipeline.py           ← これも

projects/dozle_kirinuki/scripts/  ← プロジェクト配下
  assemblyai_stt_clips.py         ← ここしか探さなかった
  generate_manga_short.py
  ...（100ファイル以上）
```

将軍は `projects/dozle_kirinuki/scripts/` だけ探して「ありません」と報告した。`scripts/`（リポジトリ直下）を見ていなかった。

## これは人間の組織でもある

新入社員が「このデータどこですか？」と聞く。先輩が「Aフォルダだよ」と答える。でもAフォルダの中にも`data/`と`archive/data/`と`backup/data/`がある。新入社員は`data/`しか見ない。

**探す場所が分散していると、見つけられない。** AIでも人間でも同じ。

## 対策3段階

### 1. 整理する（物理的解決）

```
Before:
  scripts/stt_merge.py            ← ここ
  projects/dozle_kirinuki/scripts/assemblyai_stt_clips.py  ← ここ

After:
  projects/dozle_kirinuki/scripts/stt_merge.py             ← 1箇所に統一
  projects/dozle_kirinuki/scripts/assemblyai_stt_clips.py
```

同じ種類のスクリプトは同じ場所に置く。当たり前だが、開発が長期化すると散らかる。

### 2. 検索できるようにする（インデックス）

セマンティック検索を導入済みだった。「STTマージ パイプライン」で検索すれば、ファイル名に関係なく意味で見つかる。

```bash
python3 scripts/semantic_search.py query "STTマージ パイプライン"
# → scripts/stt_merge.py (score: 0.92)
# → scripts/vocal_stt_pipeline.py (score: 0.87)
```

**問題は、これも使われていなかったこと。** 指示書に「セマンティック検索を活用せよ」と書いてあるのに。

### 3. 検索を強制する（ハーネス）

指示書に書いても使わないなら、仕組みで強制する。

```
将軍がcmd（作業指示）を書こうとする
  ↓ PreToolUseフック発火
  ↓ commandフィールドにスクリプト実行が含まれている
  ↓ セマンティック検索を自動実行
  ↓ 「類似スクリプトが見つかりました。確認しましたか？」
  ↓ 確認しないと保存できない
```

**「探せ」と言うのではなく、探さないと先に進めない仕組みにする。**

## 根本原因: ナレッジの断絶

もう一つ気づいたことがある。

ショート制作のテンプレート（手順書）には「④ AssemblyAIでクリップのword-levelタイムスタンプ取得」と書いてある。しかし、**具体的なスクリプト名が書いていない。**

```
❌ ④ AssemblyAIでクリップのword-levelタイムスタンプ取得
✅ ④ vocal_stt_pipeline.py でクリップのSTT実行
```

テンプレートに「何をするか」は書いてあるが「何を使ってやるか」が書いていない。だからAIは毎回探し直す。見つけられなければ新しく作ろうとする。

**ナレッジ（手順書）とコード（スクリプト）を紐付ける。** これだけで「既存を探さない問題」は大幅に減る。

## まとめ

AIエージェントが自分のコードベースを探索できない問題の対策：

| 段階 | 対策 | 効果 |
|------|------|------|
| 1 | 整理する | 探す場所を減らす |
| 2 | 検索できるようにする | 名前がわからなくても見つかる |
| 3 | 検索を強制する | 探さないと先に進めない |
| 4 | ナレッジに紐付ける | 探す必要がなくなる |

1と4は「環境を整える」、2と3は「仕組みで強制する」。両方やって初めて効く。

そして最も重要なのは、**この問題はAI固有ではない**ということ。人間の組織でも「Slackで共有したのに見てない」「Confluenceに書いたのに読まれてない」は日常茶飯事。

AIもチームメンバーとして扱うなら、「書いたから終わり」ではなく「見つけられる・使わざるを得ない仕組み」まで作る必要がある。
