# Geminiに漫画を描かせるプロンプト設計 — 試行錯誤20回の記録

## はじめに

マイクラ実況の切り抜きチャンネルを運営している。ショート動画を漫画形式で投稿したい。Geminiの画像生成APIで漫画パネルを自動生成する仕組みを作った。

ただし、「漫画を描いて」と言えば描いてくれるわけではない。**プロンプトの設計で品質が劇的に変わる。** 1日で20回以上の試行錯誤をした記録を共有する。

## 最終的なプロンプト構成

```
【添付画像の説明】
添付画像1枚目: シーンスクリーンショット（場面の雰囲気参考）
添付画像2枚目: おんりーのキャラクター（angry_r2表情）
添付画像3枚目: おらふくんのキャラクター（crying_r1表情）

{scene_desc — 場面の描写}
{situation — 文脈}
{director_notes — 演出指示}
{speaker}のセリフの吹き出し：「{line}」

{共通ルール}
```

たどり着くまでに発見したことを順番に紹介する。

## 発見1: リファレンス画像なしだとキャラが毎回変わる

最初はプロンプトだけで生成した。「おんりーが怒っている場面」と書くだけ。

3回生成して3回とも全く違うキャラが出てきた。髪色も服も違う。当然だ。Geminiは「おんりー」を知らない。

**解決: リファレンス画像を添付する。** キャラの表情PNGをClipboard API経由でGemini UIに貼り付けてから、プロンプトを入力する。

```python
# Clipboard貼り付け方式
await page.evaluate("""
    async ([b64, mime]) => {
        const res = await fetch(`data:${mime};base64,${b64}`);
        const blob = await res.blob();
        await navigator.clipboard.write([new ClipboardItem({ [mime]: blob })]);
    }
""", [img_base64, mime_type])
await page.keyboard.press("Control+v")
```

3枚のリファレンス（シーンスクショ + キャラ2体の表情）を貼り付けたら、3回生成しても同じキャラが出るようになった。

## 発見2: 「qnly」と「おんりー」をGeminiは区別できない

リファレンス画像を貼り付けても、プロンプトに英字キー名（qnly）と日本語名（おんりー）が混在していると、Geminiが同一人物だと認識できない。

```
❌ 添付画像2枚目: qnlyのキャラクター
   ...おんりーが腕を突き出し威圧的に睨みつける

✅ 添付画像2枚目: おんりーのキャラクター
   ...おんりーが腕を突き出し威圧的に睨みつける
```

**日本語名に統一する。** 内部キー名はシステムの都合。Geminiに渡すプロンプトでは人間が読む名前を使う。

## 発見3: 誰のセリフか書かないとわからない

```
❌ 吹き出し：「ハァ？来んなよ」
✅ おんりーのセリフの吹き出し：「ハァ？来んなよ」
```

2人いるシーンで「誰が喋っているか」をGeminiに伝えないと、間違ったキャラにセリフが付く。

## 発見4: 関係ないキャラのルールを書くと混乱する

「おおはらMENはゴーグル（サングラスではない）を頭に必ず着用」というルールがある。これをデフォルトで全パネルに入れていた。

MENが出ないシーン（おんりー + おらふ）でも「ゴーグル着用」と書いてあるため、**Geminiがゴーグルを着けた謎のキャラを追加してしまった。**

**解決: キャラ固有ルールは、そのキャラが登場するパネルにのみ適用する。**

```python
# 登場キャラのみルール適用
CHAR_RULES = {"oo_men": "ゴーグル（サングラスではない）を頭に必ず着用"}

for char_key in panel["characters"]:
    if char_key in CHAR_RULES:
        prompt += CHAR_RULES[char_key]
```

## 発見5: 「下部禁止」と書くと空白ができる

YouTubeショートはUI要素が画面下部に表示される。だから「画面下部約20%にキャラや重要な要素を配置するな」と書いた。

結果、**Geminiが下部を真っ白な空白にしてしまった。** 禁止が強すぎた。

```
❌ 画面下部約20%にキャラクターの顔や重要な要素も配置するな
✅ 吹き出しは中央〜上部に配置。絵で画面全体を隙間なく埋めろ。白い余白を作るな
```

テキスト配置の制限と、絵の描画範囲は分けて指示する。

## 発見6: 「コマ分割するな」と書かないと勝手に分割される

「大きなコマ」と指示しても、Geminiが勝手に2コマに分割してキャラの足を切ったりする。

```
scene_descでコマ分割の指示がない限り、1枚の絵として描け。
勝手にコマ分割するな。キャラの体を途中で切って別のコマにするな。
```

明示的に禁止しないとやる。

## 発見7: 遠景で描くとキャラの表情が見えない

何も指示しないと、Geminiは全身を描こうとして遠景になる。漫画は**表情が命**。

```
キャラは遠景で描くな。顔〜上半身のアップまたはミドルショットで表情が見える距離感で描く。
```

既存のアスレ動画の漫画パネルで「おんりーのアップ」「MENのアップ」と指示して成功していた。この知見をデフォルトルールに昇格させた。

## 仕組み化: 設定ファイルで管理する

20回の試行錯誤で見つけたルールをスクリプトにハードコードしたくない。次に新しいルールが見つかったら？

**全ルールをYAMLの設定ファイルに切り出した。**

```yaml
# cdp_manga_rules.yaml
common_rules:
  - "添付画像のキャラクターの外見・色・髪型・服装を正確に再現すること。"
  - "指定されたセリフ以外の吹き出し・テキストは追加するな。"
  - "キャラは遠景で描くな。顔〜上半身のアップで描く。"
  - "吹き出しは中央〜上部に配置。絵で画面全体を隙間なく埋めろ。"
  - "コマ分割の指示がない限り、1枚の絵として描け。"
  - "盾・武器・バケツは持たせるな。"

char_rules:
  oo_men: "おおはらMENはゴーグルを頭に必ず着用。"
```

スクリプトはこのYAMLを読んでプロンプトを組み立てる。ルール追加はYAMLを1行足すだけ。CDP版（UI操作）とAPI版の両方が同じ設定を使う。

## 結果

| 試行 | 問題 | 対策 |
|------|------|------|
| 1-3回 | キャラが毎回違う | リファレンス画像添付 |
| 4-5回 | 2人を区別できない | 日本語名統一 |
| 6-7回 | セリフの話者不明 | 話者名明記 |
| 8-9回 | 関係ないキャラが出る | キャラ固有ルール限定 |
| 10-12回 | 下部が空白 | 禁止文言の調整 |
| 13-15回 | 勝手にコマ分割 | 明示的禁止 |
| 16-18回 | 遠景で表情見えない | アップ指示 |
| 19-20回 | ルールのハードコード | YAML設定ファイル化 |

最終的に、同一プロンプトで3回生成しても、キャラの外見・構図・セリフ配置が一貫するようになった。

## まとめ

Geminiに漫画を描かせるプロンプト設計のコツ：

1. **リファレンス画像は必須。** 「描写」だけではキャラの一貫性は保てない
2. **名前はプロンプト全体で統一。** 内部キー名と表示名を混ぜない
3. **やってほしくないことは明示的に禁止。** 言わないとやる
4. **ルールは設定ファイルに切り出す。** ハードコードしない
5. **登場キャラに関係ないルールは入れない。** 混乱の元
